# FDE 现场价值闭环

本参考从 [FDE Guidance Book](https://github.com/xdash/FDE-the-Guidance-Book-of-Forward-Deployed-Engineer) 的“解决正确的问题、赢得客户、激活部署、守住续约、扩大收入、规模化复制”主线提炼为可执行闭环。只保留会改变 Agent 行为的判断与完成标准。

## 1. 现场侦察

用参与式观察或同等强度的运行证据重建真实工作，不只阅读正式流程。

建立五张地图：

1. **数据地图**：数据源、所有者、质量、权限、实际被信任的版本。
2. **流程地图**：真实步骤、例外、绕行、手工复制和等待点。
3. **组织地图**：发起者、买单者、使用者、否决者、知识枢纽。
4. **系统地图**：接口、部署、合规、变更窗口和依赖负责人。
5. **政治地图**：受益者、受威胁者、权力变化和潜在阻力。

完成标准：指出一个具体用户、一个具体痛点、一个可信数据源、一个结果负责人和一个可观测信号。

## 2. PSF 与拒绝机制

同时验证痛点、经济性和可行性。把“提高效率”改写为带频率、时长、错误后果和责任人的现场事实。

高危信号：

- 只有 IT 对接，没有业务结果负责人；
- 只要求供应商证明能力，却不给代表性真实数据；
- 首次交付要求覆盖全公司或所有场景；
- 客户按人头派活，交付无法沉淀为可复用能力；
- 验证没有期限、阈值和裁判。

出现关键前提缺失时，输出补齐路线与重新评估时间，不用技术热情掩盖 `defer` 或 `reject`。

## 3. 赢得内部客户

优先选择既能产生结果、又能产生可复用学习与可信背书的灯塔场景。建立多层支持者网络，避免单点 champion。

将采购、法务和安全审查视为交付能力：准备分阶段结果承诺、数据使用边界、责任模型、架构和数据流图、权限与审计说明。信任应被产品化，而不是临近签约才临时解释。

在提交方案前回答：客户成功后是否愿意公开或私下背书？这个客户会塑造怎样的产品方向？交付学习能否服务同类客户？

## 4. Minimum Viable Deployment

MVD 验证“这个方案能否在这个客户的真实环境里产生价值”。

军规：

- 使用代表性真实数据；
- 缩小范围，不稀释端到端价值；
- 验证周期以周计；
- 启动前写明毕业、迭代和停止条件；
- 让真实业务方使用并裁决；
- 对旧环境“读旧写新”：读取真实旧数据，但把可撤离的新能力放在可控边界内。

一个合格 MVD 至少包含：基线、目标、场景边界、数据、集成、权限、评估集、回滚、责任人和截止时间。

## 5. 激活部署

上线不等于激活。围绕 Time to Value 建立紧反馈循环：高频小步部署、真实评估集、日志与行为采集、快速修复、必要时有损降级。

同时处理三类阻力：

- **产品阻力**：入口、交互和工作流不符合用户习惯；
- **系统阻力**：身份、数据、接口、网络、合规、发布流程；
- **组织阻力**：缺乏培训、当地支持者和受影响角色的新位置。

交付自动化的优先级高于继续增加人工操作：环境检查、接入、评估、发布、健康监控和报告应逐步工具化。

## 6. 守住续约

续约从首次价值产生时开始。持续维护：

- 性能、稳定性和质量趋势；
- 新用户首日与首周激活；
- 多层支持者覆盖；
- 使用、价值、关系和商业健康信号；
- 异常下降后的自动唤醒与干预。

允许有损服务：关键路径优先保持可用，非关键智能能力可以降级或回退到人工。不要为了理论完美牺牲客户连续运营。

## 7. 扩大价值

用价值账本而不是功能清单推动扩张。每条扩张线说明：新增用户或流程、额外业务结果、所需环境能力、边际交付成本和新的支持者。

优先从相邻部门和相似流程扩张，让已有数据、集成、信任和评估集产生复用。计价从用量逐步靠近行为、结果或价值，但只使用双方能审计、能归因的指标。

## 8. 复利现场学习

使用三层复制杠杆：

1. **打法手册**记录判断：场景痛点、尽调、高危信号、雷区、验收指标、角色地图、计价和失败教训。
2. **组件库**沉淀手艺：连接器、schema、评估器、部署与运维自动化。
3. **平台**固化能力：让常见工作自助化，让 FDE 只攻坚新的不确定性。

产品化前回答四问：

1. 同类问题是否在至少三个独立现场重复出现？
2. 泛化成本是否低于未来重复定制成本？
3. 非工程师能否安全使用？
4. 平台化后是否仍给现场保留解决新问题的空间？

失败部署也必须进入复盘传播：记录错误假设、可观测信号、发现时机和下次拒绝或止损条件。

## 9. 退出与知识转移

FDE 的结束状态不是长期驻场，而是客户能够独立运营。交付：运行手册、监控与告警、权限清单、回滚、已知限制、值班与升级路径、培训记录、指标口径和后续产品反馈入口。

完成标准：客户方明确接手日常操作和一线判断；FDE 只保留约定的升级支持与新问题共创。
