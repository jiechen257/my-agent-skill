# 双周报格式唯一规范

本文件是 `biweekly-report-template` 的格式唯一来源。先选择一个模式，再严格使用对应结构。

## 通用元信息与命名

`personal` 和 `portfolio` 模式使用以下元信息：

```markdown
- 周期：YYYY-MM-DD 至 YYYY-MM-DD
- 范围：[主题、模块或项目组合]
- 统计口径：基于两份周报合并整理，按工作流主题重新归并双周进展
- 来源：`<week-1>`、`<week-2>`
- 使用技能：`biweekly-report-template`
```

`module` 模式把同样字段写成加粗标签，不增加文档级标题。周期为闭区间并与文件名一致。标准双周包含连续且不重叠的 14 天；用户明确指定其他周期时如实记录，不补齐日期。

默认文件名：

```text
YYYY-MM-DD-to-YYYY-MM-DD-biweekly-summary.md
```

显式模式或范围可放在日期后：

```text
YYYY-MM-DD-to-YYYY-MM-DD-<mode-or-scope>-biweekly-summary.md
```

## Personal：默认个人四段式

只保留一个标题、五行元信息和四个有序章节。列表层级与周报一致：顶层 `1.`–`4.`；工作流层缩进 2 空格并使用连续 `a.`、`b.`；双周明细层缩进 4 空格并使用连续 `ⅰ.`、`ⅱ.`。禁止 ASCII `i.` / `ii.`，每个工作流至少有一条明细。

```markdown
# 陈洁双周报

- 周期：YYYY-MM-DD 至 YYYY-MM-DD
- 范围：[主题范围]
- 统计口径：基于两份周报合并整理，按工作流主题重新归并双周进展
- 来源：`../weekly/<week-1>.md`、`../weekly/<week-2>.md`
- 使用技能：`biweekly-report-template`

1. 双周进展概述：[一句话概述]
2. 双周进展明细：
  a. [工作流 1][，进度：仅在来源明确支持时填写]
    ⅰ. [结果与阶段变化]
    ⅱ. [结果与阶段变化]
  b. [工作流 2]
    ⅰ. [结果与阶段变化]
3. 下阶段里程碑：[一句话概述]
4. 下阶段计划明细：
  a. [可验证计划 1]
  b. [可验证计划 2]
```

正文除标题外不使用 Markdown 标题。工作流数量由证据决定，不创建空工作流或凑数的“其他”。

## Portfolio：项目组合式

用于显式的多项目回顾。标题默认 `# 陈洁项目双周报`，固定一级结构为：

1. `## 双周总览`
2. `## 项目/仓库总结`
3. `## 双周推进索引`
4. `## 下阶段优先级`

`项目/仓库总结` 下用 `### 项目：<name>`。每个项目固定使用加粗标签 `**双周进展概述：**`、`**双周进展明细：**`、`**下阶段里程碑：**`、`**下阶段计划明细：**`，内容使用列表。项目组合模式可以保留时间索引，但不能把 commit 流水账当作总结。

## Module：可嵌入模块版

模块版不使用文档标题。元信息和正文示例：

```markdown
**周期：** YYYY-MM-DD 至 YYYY-MM-DD
**范围：** [模块范围]
**统计口径：** 基于两份周报合并整理
**来源：** `<week-1>`、`<week-2>`
**使用技能：** `biweekly-report-template`

#### [模块名称]

**双周进展概述：** [一句话概述]

**双周进展明细：**

- [主题 1]
  - [结果与阶段变化]
- [主题 2]
  - [结果与阶段变化]

**下阶段里程碑：** [一句话概述]

**下阶段计划明细：**

- [可验证计划 1]
- [可验证计划 2]
```

目录中只允许 `####` 模块标题；禁止 `#`、`##`、`###`。模块内部的概述、明细、结论、里程碑、计划和动作只能使用加粗标签与列表。

## 状态与 OKR 门禁

- `开发中`、`待提测`、`已提测`、`已上线`、`已完成` 只有在输入材料明确支持时才能出现。
- 合并两周材料不得提升状态；若第二周没有更新，保留最近一次明确状态或省略状态。
- OKR 对齐不是默认章节。仅在用户明确要求时添加，并把实际读取的 OKR 文件列入 `来源`。
- `personal` 模式经授权可在四段正文后增加 `## OKR 对齐补充`；`portfolio` 可增加同名一级章节；`module` 使用 `**OKR 对齐补充：**`，仍不得增加 `#`–`###` 标题。

## 内容边界

- 以两份周报为主证据，不把重复事项算成两项产出。
- 不出现 commit hash、原始 commit subject、文件数、代码行数或 diff 统计。
- 不把“计划”“讨论”“待验证”改写成“完成”“上线”或量化效果。
- 下阶段计划优先继承来源周报中的未闭环事项；纯推导时使用“验证”“收口”“推进”。
