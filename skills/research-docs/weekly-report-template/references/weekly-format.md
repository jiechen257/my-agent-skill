# 周报格式唯一规范

本文件是 `weekly-report-template` 的格式唯一来源。它只规定最终产物，不负责采集证据。

## 固定结构

报告由一个标题、五行元信息和五个有序章节组成。章节数量与顺序不可改变：

1. `阶段目标`
2. `数据看板 & 分析`
3. `周进展`
4. `遗留问题`
5. `本周目标与计划`

列表标记与缩进固定为：

- 顶层：`1.`、`2.`、`3.`、`4.`、`5.`，不缩进。
- 工作流层：`a.`、`b.`、`c.`，缩进 2 个空格并连续编号；五个章节都至少有一条。
- 可选明细层：`ⅰ.`、`ⅱ.`、`ⅲ.`，缩进 4 个空格，并在每个 `a.` 项内从 `ⅰ.` 重新连续编号。
- 禁止用 `i.`、`ii.`、`iii.` 代替 Unicode 罗马数字。
- 正文除文档标题外不使用 Markdown 标题，不使用无序 `-` 列表。

## 元信息

标题默认是 `# 陈洁周报`；用户指定其他 owner 时替换姓名。标题下依次保留：

```markdown
- 周期：YYYY-MM-DD 至 YYYY-MM-DD
- 范围：[本周覆盖的工作流 / 模块主题]
- 统计口径：本周本人 Git 提交、[实际使用的补充材料或工作区检查]
- 来源：[业务仓库 Git 提交记录、关键文档路径或获批材料]
- 使用技能：`weekly-report-template`
```

- `周期` 使用闭区间，并与文件名日期一致；周一至周日是默认单周范围。
- `范围` 写主题，不写一串裸仓库名；不得把 `daily-report` 当作默认业务范围。
- 使用 Git 时，`统计口径` 必须说明是“本人”提交，并按 owner 过滤、按 commit hash 去重。
- `来源` 只列实际读取的输入。
- `使用技能` 固定为 `` `weekly-report-template` ``。

## 输出骨架

```markdown
# 陈洁周报

- 周期：YYYY-MM-DD 至 YYYY-MM-DD
- 范围：[主题范围]
- 统计口径：本周本人 Git 提交、[其他实际口径]
- 来源：[实际输入]
- 使用技能：`weekly-report-template`

1. 阶段目标：
  a. [本阶段目标]
2. 数据看板 & 分析：
  a. [指标、分母、趋势和结论]
3. 周进展：
  a. [已完成的功能 / 需求点 / Bug 修复 / 联调或验证交付物 + 作用]
4. 遗留问题：
  a. [未解决问题、依赖或证据缺口]
5. 本周目标与计划：
  a. [本周要开发 / 修复 / 联调 / 发布 / 验证的具体功能或需求 + 可验证结果]
```

`数据看板 & 分析` 不得只写结论而省略关键分母；当窗口级 UV、发布状态或因果关系无法确认时，必须在该节或 `遗留问题` 中明确说明。`遗留问题` 不得留空；没有新增问题时写“无新增遗留问题”。

`周进展` 回答“上周具体做成了什么”：必须以功能、需求点、Bug 修复、联调或验证交付物为主体，再补充作用或指标效果；纯指标变化、日志分析和问题发现只进入 `数据看板 & 分析` 或 `遗留问题`。`本周目标与计划` 回答“本周具体要做什么”：每项都要包含工作对象、动作和可验证结果；“保持成功率”“跟进异常”不能单独成项。

## 内容边界

- 不按仓库、日期或 commit 拆顶层叙事；跨仓共享主题合并为同一工作流。
- 不出现 commit hash、commit subject 原文、shortlog、文件数、代码行数、diff 统计或无解释的文件路径。
- 不把讨论、计划、工作区改动写成已完成、已上线、已推广或效果良好；没有对应指标或验证证据时使用“推进”“验证”“收口”“补齐”。
- 不把 PV/UV、成功率、失败率、耗时或错误分布本身写成 `周进展`；这些指标只能作为具体交付项的效果证据或计划优先级依据。
- 不为文档、群聊或调研单独建工作流，除非它本身形成明确交付物。
- 没有采用率或效果证据时，只描述接入、联调、验证或收口状态。

## 输出与保存

- Chat-only：直接返回完整 Markdown。
- Local saved：优先遵循当前项目 `AGENTS.md`；否则存在 `weekly/` 时写入该目录。
- Paste-ready：只返回可粘贴 Markdown，不在报告前后添加说明。
- 同时要求保存和粘贴时，先保存，再返回同一份内容。

默认文件名：

```text
YYYY-MM-DD-to-YYYY-MM-DD-weekly-summary.md
```

同周期已有不同范围的文件时，追加小写范围后缀，不覆盖现有文件：

```text
YYYY-MM-DD-to-YYYY-MM-DD-<scope>-weekly-summary.md
```
