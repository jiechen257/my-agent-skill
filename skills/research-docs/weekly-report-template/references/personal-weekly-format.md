# 之瓷周报格式

标题为 `# 之瓷周报`，可用 `｜` 加短主题。紧接标题写 `**统计周期：**YYYY-MM-DD 至 YYYY-MM-DD（北京时间）`，日期为闭区间。正文按示例使用六个连续的加粗编号标题。引用附在对应段落或表格说明末尾。使用 Git 时，在来源说明写清按本人作者身份过滤、按提交哈希去重。

1. **阶段目标**。简述 Query 分析与问题治理、夸克会议纪要当前要达成的结果。
2. **业务 & 研发核心指标数据**。主表和补充说明仅覆盖以下三项。OKR 目标和基线从当前正式 OKR 读取。结果或基线缺失时保留对应单元格并注明缺口。
3. **与 OKR 关联的目标进展**。说明本期的实际产出推进了哪项 KR，有哪些验证结果或待补证据。
4. **周进展**。依次写【录音纪要】、【Query 抽检平台】、【其他】。每块可补状态，明细按本期实际工作写。没有本期证据时写“本期无可确认进展”。常见内容见示例，不固定小点数量。
5. **问题与风险**。记录影响复验、数据解释或排期的问题。确实没有时写“无新增问题与风险”。
6. **周目标与计划**。用表格写【Query 分析与问题治理】、【夸克会议纪要需求】两行，列明本周、下周。按团队排期用各周周一标注日期。每格写对象、动作和可验证结果，未知时写“待确认”。

正文骨架如下，方括号内为写作提示：

```markdown
# 之瓷周报

**统计周期：**YYYY-MM-DD 至 YYYY-MM-DD（北京时间）。

1. **阶段目标**
   - [阶段目标]

2. **业务 & 研发核心指标数据**

   | 指标 | OKR 目标 | 正式基线 | 本期回收与分析 |
   | --- | --- | --- | --- |
   | **Agent 任务交付成功率**（当前观测：线上任务正常完成率） | [OKR 目标] | [窗口、分子、分母和比率] | [同口径上期、本期、变化和达成情况] |
   | **Query 分析问题回收情况** | [问题治理 KR] | [正式基线或缺口] | [Aone 回收范围、去重关系、状态和复验依据] |
   | **无效工具调用比例** | [OKR 目标及约束] | [抽检窗口、无效/总调用、待判] | [同口径复测或缺口] |

   [OKR、查询窗口和取数来源]

3. **与 OKR 关联的目标进展**
   - [实际产出与对应 KR]

4. **周进展**
   1. **【录音纪要】** [当前进度]
      1. [各端方案和边界处理、上下游联调、iTrace 异常监控等实际进展]
   2. **【Query 抽检平台】** [当前进度]
      1. [三端 Agent 真实 Query 对照、Trace 工具信息采集与展示等实际进展]
   3. **【其他】**
      1. [其他已确认的工作]

5. **问题与风险**
   - [实际问题与风险]

6. **周目标与计划**

   | 核心目标 | 本周（M 月 D 日当周） | 下周（M 月 D 日当周） |
   | --- | --- | --- |
   | **Query 分析与问题治理** | [本周动作与验收] | [下周动作与验收] |
   | **夸克会议纪要需求** | [本周动作与验收] | [下周动作与验收] |
```

根据请求返回聊天正文或保存本地文件。默认在存在的 `weekly/` 保存为 `YYYY-MM-DD-to-YYYY-MM-DD-weekly-summary.md`。同周期已有不同范围的报告时使用 `-<scope>-weekly-summary.md`，避免覆盖。
