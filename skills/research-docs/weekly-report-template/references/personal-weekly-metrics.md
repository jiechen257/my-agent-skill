## Agent 任务交付成功率

- 按 OKR 当前口径观测线上任务正常完成率，标明它衡量执行终态。若 OKR 新增产物交付验收口径，按其定义报告产物可用性。
- 使用 `itrace-cli` 读取 OKR 指定的 iTrace 看板与视图，先确认配置。当前入口为应用 `lxfs0q6t-cck1z5z5` 的「任务可用性」3012 / 「完成率」15702。以现行 OKR 确认生产环境、非阿里云运营商、客户端版本 ≥4.0.0、`cowork_agent/invoke_agent` 等筛选。当前正常完成要求 `biz.status.code=ok` 且 `dim_3=stop`。
- 取本期和上期两个独立等长周，汇总窗口总正常完成数与总任务数后相除。取消、失败及其他终态按 OKR 保留在分母。核对每日桶完整性，报告分子、分母、百分点变化和目标差距。OKR 基线单列，即使它与报告周期重叠。

## Query 分析问题回收情况

- 从 OKR 问题治理 KR 取目标和基线，回收表里缺少正式基线时写“尚未建立”。可用过往提出的 Aone Bug 做回收样本。明确样本范围、回读时间、状态和关联关系，区分本期新增和历史存量。
- 通过只读查询核对实际工单、处理状态、修复版本和复验结果。保留主单与关联单的原始状态，按问题类型汇总时避免双计。Won’tfix 或关闭状态本身不足以计为修复通过。只有固定回归集执行结果和对应修复版本齐全时才报告复验达成。人工耗时按 OKR 约定的相同步骤和计时边界比较。

## 无效工具调用比例

- 从 OKR 取得目标、基线以及任务正常完成率不下降等约束。复测沿用同样的抽样窗口规则、场景配比和判定条件。按调用 ID 去重，报告确认无效次数 / 总调用次数，另列待判次数及其影响。保留取消、失败和缺证样本，避免用点踩比例、工具失败率或总调用量替代。
- 本期缺少等口径抽检时，展示 OKR 历史基线并标注“本期暂无同口径复测”，避免将基线写作本期实测。
