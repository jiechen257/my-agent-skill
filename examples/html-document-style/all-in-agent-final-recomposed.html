4.3　回顾 & 挑战

挑战 1｜集中建设力度还不够，个人技能没有变成团队技能

好工具在团队的覆盖度不够，AI 技巧共享不够；D2C 效果、功能验证、客户端 AI Native 架构升级都存在分散建设的问题——每个团队各自一套流程，最佳实践没有沉淀下来。

挑战 2｜高估了 AI Coding 的代码质量

对「团队同学都能用 AI Coding 交付高质量代码和功能」评估不足。以千问输入法为例：前期 2 个人几天就做出 Demo，团队信心大增；但真正项目化后版本速度并没有快起来，投入持续增大、代码持续重构、Bug Reopen 率高，最后靠不断增加门禁、熟悉 AI 写的代码才把质量和节奏稳下来。Demo 的速度不等于版本的速度，差的那部分就是门禁、上下文与验证体系。

4.5　策略 & 规划
  1. 测试左移：研发是质量的第一责任人，通过优化需求质量、分层单测和 AI 测试降低 Bug 数。
  2. 鸿蒙转码：鸿蒙版本比 Android、iOS 晚一个版本，建设可用性高的鸿蒙转码 Agent，同时考虑二级页引入 CMP。
  3. 明确团队的 AI Native 工作流：以 AI Native 工作台和 QBoz 为基础，把 Spec、测试用例、验证作为必须项；每个需求由 Owner 把关方案与质量，各团队可做定制。
  4. AI 友好的架构改造：各个工程都要做 AI 友好的架构改造。
  5. 擅长的任务做到自动 Loop：Hotfix、卡片开发、Code Review、答疑、告警与自动排查等，做到自动 Loop 并持续提升交付效果。
  6. AI Native 工作台：往 AI Native 工作台升级，在样板间项目试点工作台，解决多团队协作的信息共享，Agent 作为超级大脑承担项目管理和托管执行的能力。
  7. 集中建设 Agent 工具：QBoz、知识库、验证、Mock 系统、提 Bug 工具、D2C 等。

五

团队要求

中短期看，AI 时代对人的要求更高

5.1　工程师的定位
前提：AI 程序员跟传统程序员已经完全不一样了。
定位说明
Agent 工程师建设 Agent 给外部用户使用，对标 WorkBuddy、豆包工作。
AI 程序员应用 Agent、基于 Agent 交付功能；善于使用 AI，持续优化 Coding Agent 能力，构建 AI 需要的上下文，在领域技能上一专多能。
传统程序员AI 参与度低，传统流程，传统技能。
5.2　具体要求 基础、转型、架构
  1. 扎实的基础：更好的判断力、架构能力、沟通能力、快速学习能力和技术基础。AI 是一个放大器，人写代码变少后，对代码的熟悉度、敏感度在下降，基础不牢，构建起来的产品和工程就如空中楼阁。
  2. 全员 Agent 转型：用 AI 重新设计团队和个人的核心流程，新流程以 AI 为前提；熟悉 Agent 运行原理，具备建设和优化 Agent 的能力。
  3. 全员具备架构能力：运营业务组做全栈的尝试；客户端做跨端的实践，一人两端、三端。
总结

大模型是一场智力革命，是未来最大的确定性，新的产品形态、团队形态甚至社会形态都在围绕它变革。旧时代的复利已经开始下降，新时代的复利开始了。
